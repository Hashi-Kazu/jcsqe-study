# 2章 ソフトウェア品質マネジメント — 2.1.2：セキュリティのマネジメント

> 出典 : `/intermediate/syllabus/CH2_intermediate_syllabus.md`

## 🌟 学習目的
セキュリティのマネジメントの概念や技術の使い方がわかっており、それらを適切に選択して、限られた条件の下で与えられた課題を解決できる。

---

## 🧠 学習対象となる用語，概念
1. **セキュリティのマネジメント**:
    - **定義**: 組織の情報資産を、機密性、完全性、可用性の観点から保護するための体系的な活動。リスクアセスメントに基づき、適切なセキュリティ対策を計画、実施、監視、改善する。
    - **解説**: ソフトウェア開発においては、開発プロセス全体を通じてセキュリティを考慮することが重要。設計段階でのセキュリティ要件定義、セキュアコーディング、脆弱性テストなどが含まれる。
2. **コモンクライテリア**:
    - **定義**: ISO/IEC 15408として国際標準化されている、情報技術セキュリティ評価のための国際標準。IT製品やシステムのセキュリティ機能と保証レベルを評価するための枠組みを提供する。
    - **解説**: 評価対象のセキュリティ機能（SFR: Security Functional Requirements）と、その機能がどの程度信頼できるかを示す保証レベル（SAR: Security Assurance Requirements）を定義する。EAL（Evaluation Assurance Level）という7段階の保証レベルがある。
3. **ISMS（情報セキュリティマネジメントシステム）**:
    - **定義**: Information Security Management Systemの略。組織の情報セキュリティを管理するための体系的な仕組み。ISO/IEC 27001がその要求事項を定めている。
    - **解説**: 情報資産の特定、リスクアセスメント、リスク対応計画の策定、セキュリティ対策の実施、監視、レビュー、改善というPDCAサイクルを回すことで、情報セキュリティを継続的に維持・向上させる。
4. **CC/CEM**:
    - **定義**: コモンクライテリア（CC）と、その評価方法論（CEM: Common Methodology for Information Technology Security Evaluation）の総称。
    - **解説**: CCが評価の「基準」であるのに対し、CEMは評価を「どのように行うか」を定めたもの。これらを合わせて用いることで、IT製品やシステムのセキュリティ評価を客観的かつ一貫性のある方法で実施できる。

---

## 📌 頻出論点／出題パターン
- **情報セキュリティの3要素**: 機密性、完全性、可用性の3要素は基本中の基本。それぞれの意味と、具体的なセキュリティ対策がどの要素に貢献するかを理解する。
- **ISMSのPDCAサイクル**: ISMSがPDCAサイクルを回しながら継続的に改善される仕組みであることを理解する。
- **コモンクライテリアの目的**: IT製品やシステムのセキュリティ評価を客観的かつ国際的に統一された基準で行うためのものであることを理解する。EALの概念も重要。
