# 2章 ソフトウェア品質マネジメント — 2.3.1：ソフトウェアプロセス評価モデル

> 出典 : `/intermediate/syllabus/CH2_intermediate_syllabus.md`

## 🌟 学習目的
ソフトウェアプロセス評価モデルの概念や技術の使い方がわかっており、それらを適切に選択して、限られた条件の下で与えられた課題を解決できる。

---

## 🧠 学習対象となる用語，概念
1. **ソフトウェアプロセス評価モデル**:
    - **定義**: ソフトウェア開発プロセスの成熟度や能力を客観的に評価するための枠組み。組織のプロセス改善活動の指針となる。
    - **解説**: 組織のプロセスがどのレベルにあるかを診断し、改善の方向性を示す。CMMIやISO/IEC 33000シリーズなどが代表的。
2. **CMMI（能力成熟度モデル統合）**:
    - **定義**: Capability Maturity Model Integrationの略。ソフトウェア開発組織のプロセス改善を支援するためのフレームワーク。プロセスの成熟度を5段階（初期、マネージド、定義済み、定量的に管理された、最適化）で評価する。
    - **解説**: 各成熟度レベルにおいて、組織が達成すべきプロセス領域（PA: Process Area）と、その達成に必要なプラクティスが定義されている。成熟度レベルが上がるほど、プロセスの予測可能性と品質が向上するとされる。
3. **プロセスアセスメントに関する規格（ISO/IEC 33000シリーズ）**:
    - **定義**: ソフトウェアおよびシステムエンジニアリングのプロセスアセスメントに関する国際規格群。ISO/IEC 15504（SPICE）の後継。
    - **解説**: プロセスアセスメント（プロセス評価）の実施方法や、評価結果の報告方法などを定めている。CMMIのような特定のプロセスモデルに依存せず、様々なプロセスモデルの評価に適用できる汎用的なフレームワークである。
4. **Automotive SPICE**:
    - **定義**: 自動車産業に特化したソフトウェアプロセス評価モデル。ISO/IEC 33000シリーズ（旧ISO/IEC 15504）をベースに、自動車業界の要求事項を加えて策定された。
    - **解説**: 自動車の電子制御システム開発において、サプライヤーのプロセス能力を評価するために広く用いられている。機能安全（ISO 26262）との関連も深い。
5. **ISO/IEC 33000シリーズ**:
    - **定義**: 既出。ソフトウェアおよびシステムエンジニアリングのプロセスアセスメントに関する国際規格群。
    - **解説**: プロセスアセスメントの実施方法や、評価結果の報告方法などを定めている。CMMIのような特定のプロセスモデルに依存せず、様々なプロセスモデルの評価に適用できる汎用的なフレームワークである。
6. **TMMi（テスト成熟度モデル統合）**:
    - **定義**: Test Maturity Model Integrationの略。テストプロセスの成熟度を評価するためのモデル。CMMIをベースに、テストに特化して拡張されたもの。
    - **解説**: テストプロセスがどのレベルにあるかを診断し、テスト活動の改善を支援する。テストの計画、設計、実行、評価などのプロセス領域が含まれる。
7. **TPI（テストプロセス改善）**:
    - **定義**: Test Process Improvementの略。テストプロセスの改善を目的としたフレームワーク。テストプロセスの現状を分析し、改善点を特定するためのチェックリストやガイダンスを提供する。
    - **解説**: TMMiと同様にテストプロセスの改善を目的とするが、TPIはより実践的な改善活動に焦点を当てている。

---

## 📌 頻出論点／出題パターン
- **CMMIの成熟度レベル**: 5段階の成熟度レベル（初期、マネージド、定義済み、定量的に管理された、最適化）と、それぞれのレベルの特徴を理解する。特に、レベル2（マネージド）とレベル3（定義済み）の違いは頻出。
- **CMMIとISO/IEC 33000シリーズ（SPICE）の違い**: CMMIが特定のプロセスモデルであるのに対し、ISO/IEC 33000シリーズはプロセスアセスメントの「方法論」を定めた汎用的な規格であるという違いを理解する。
- **Automotive SPICEの目的**: 自動車産業におけるソフトウェア開発プロセスの評価に特化していることを理解する。
- **TMMiとTPIの目的**: テストプロセスの改善を目的としたモデル・フレームワークであることを理解する。
