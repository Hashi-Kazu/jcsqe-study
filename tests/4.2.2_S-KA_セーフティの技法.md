# 4章 専門的なソフトウェア品質の概念と技術 — 4.2.2：セーフティの技法

> 出典 : `/intermediate/syllabus/CH4_intermediate_syllabus.md`

## 🌟 学習目的
セーフティの技法の概念や技法の使い方がわかっており、それらを適切に選択して、限られた条件の下で与えられた課題を解決できる。

---

## 🧠 学習対象となる用語，概念
1. **セーフティの技法**:
    - **定義**: システムの安全性を確保し、危害のリスクを許容可能なレベルまで低減するための具体的な手法。
    - **解説**: ハザード分析、リスク低減、フォールトトレランス、フェイルセーフ、STAMP/STPAなどが含まれる。特にセーフティ・クリティカルシステムにおいて重要となる。
2. **MC/DC**:
    - **定義**: Modified Condition/Decision Coverageの略。ホワイトボックステストにおける網羅基準の一つ。各条件が、決定の真偽に独立して影響を与えることを確認する。
    - **解説**: 航空機制御ソフトウェアなど、極めて高い安全性が求められるシステムで用いられる。高い網羅性を要求するため、テストケース数が多くなる傾向がある。
3. **STAMP**:
    - **定義**: 既出。System-Theoretic Accident Model and Processesの略。システム全体の安全性を、システム理論に基づいて分析するためのモデル。
    - **解説**: 従来の故障連鎖モデル（原因→結果）ではなく、システム全体の制御構造や相互作用の観点から事故を分析する。ソフトウェアの安全分析に有効。
4. **STPA**:
    - **定義**: 既出。System-Theoretic Process Analysisの略。STAMPをベースとした、システム安全分析手法。
    - **解説**: 制御システムの不安全な制御アクションを特定し、その原因を分析することで、事故を未然に防ぐことを目指す。ソフトウェアの安全分析に有効。
5. **アクシデントモデル**:
    - **定義**: 既出。事故が発生するメカニズムや要因を体系的に表現したモデル。
    - **解説**: 故障連鎖モデル、スイスチーズモデル、STAMPなど、様々なアクシデントモデルが存在する。これらのモデルを用いて事故を分析することで、再発防止策を検討できる。
6. **アクティブセーフティ**:
    - **定義**: 事故を未然に防ぐための安全対策。危険を予測し、回避行動を支援する機能。
    - **解説**: 例えば、自動車の衝突被害軽減ブレーキ、車線逸脱警報システムなど。危険を回避することで、事故の発生確率を低減する。
7. **エラープルーフ**:
    - **定義**: ポカヨケとも呼ばれる。人間の誤操作や間違いを物理的、あるいはシステム的に不可能にする、または困難にする設計。
    - **解説**: 例えば、USBコネクタの差し込み方向を限定する、入力フォームで必須項目を未入力のまま送信できないようにするなど。ヒューマンエラーによる欠陥の発生を抑制する。
8. **エラー推測テスト**:
    - **定義**: 既出。過去の経験や知識に基づいて、欠陥が混入しやすい箇所や、発生しやすい欠陥の種類を推測し、それらを重点的にテストする技法。
    - **解説**: セーフティ・クリティカルシステムにおいては、潜在的な危険性を早期に発見するために活用される。
9. **セーフティ実現のためのリスク低減技法**:
    - **定義**: システムの安全性を確保するために、危害のリスクを許容可能なレベルまで低減するための様々な手法。
    - **解説**: 固有安全、機能安全、フォールトトレランス、フェイルセーフ、フェイルソフトなどが含まれる。
10. **セーフティ・クリティカルシステム**:
    - **定義**: 既出。故障や誤動作が発生した場合に、人命、環境、財産に重大な危害を及ぼす可能性のあるシステム。
    - **解説**: これらのシステムでは、極めて高い安全性が求められるため、特別なセーフティの技法が適用される。
11. **セーフティ・クリティカルシステムのテスト**:
    - **定義**: セーフティ・クリティカルシステムに対して、その安全性を検証するために行われるテスト。
    - **解説**: MC/DCなどの高い網羅基準を満たすテスト、ハザードに対するシナリオテスト、安全機能に対するテストなどが含まれる。独立した第三者によるテスト（IV&V）も重要。
12. **ハザードに対するシナリオテスト**:
    - **定義**: 特定のハザード（危険源）が発生するシナリオを想定し、そのシナリオにおいてシステムが安全に振る舞うかを確認するテスト。
    - **解説**: 例えば、「ブレーキが故障した場合に、システムがどのように安全に停止するか」といったシナリオをテストする。
13. **ハザードの推測**:
    - **定義**: システムに潜在するハザード（危害を引き起こす可能性のある状態または状況）を特定する活動。
    - **解説**: FMEA、FTA、HAZOPなどの手法が用いられる。ハザードを漏れなく特定することが、安全設計の第一歩となる。
14. **パスの同定**:
    - **定義**: プログラムの実行パスを特定すること。ホワイトボックステストにおいて、テストケースがどのパスを網羅しているかを確認するために用いられる。
    - **解説**: MC/DCなどの網羅基準を満たすためには、特定のパスを網羅するテストケースを設計する必要がある。
15. **パッシブセーフティ**:
    - **定義**: 事故が発生した際に、被害を軽減するための安全対策。危険を吸収し、被害を最小限に抑える機能。
    - **解説**: 例えば、自動車のエアバッグ、シートベルト、衝撃吸収ボディなど。事故の発生を前提とした対策。
16. **フェイルオーバー**:
    - **定義**: システムの一部に障害が発生した場合に、自動的に予備のシステムやコンポーネントに切り替えることで、サービスを継続する機能。
    - **解説**: 可用性を高めるためのフォールトトレランス技術の一つ。システムの停止時間を最小限に抑える。
17. **フェイルセーフ**:
    - **定義**: システムに故障が発生した場合に、安全な状態に移行する、または安全な状態を維持する設計思想。
    - **解説**: 例えば、信号機が故障した場合に、全赤信号になることで衝突を防ぐなど。故障しても危害が発生しないようにする。
18. **フェイルソフト**:
    - **定義**: システムに故障が発生した場合に、一部の機能を停止させたり、性能を低下させたりすることで、システム全体が停止することを防ぎ、最低限のサービスを継続する設計思想。
    - **解説**: 例えば、Webサービスの一部機能が停止しても、主要な機能は利用できるようにするなど。可用性を高めるためのフォールトトレランス技術の一つ。
19. **フォールト・アボイダンス**:
    - **定義**: 欠陥（フォールト）がシステムに混入するのを未然に防ぐための対策。品質作り込みの活動。
    - **解説**: レビュー、静的解析、コーディング規約の遵守、形式手法などが含まれる。欠陥の発生を抑制することで、システムの信頼性を高める。
20. **フォールト・トレランス**:
    - **定義**: システムに故障（フォールト）が発生しても、その故障の影響を吸収し、システム全体が停止することなく、サービスを継続する能力。
    - **解説**: 冗長化、フェイルオーバー、チェックポイント・リカバリなどが含まれる。システムの可用性や信頼性を高めるための技術。
21. **リスク低減**:
    - **定義**: 危害のリスクを許容可能なレベルまで低減するための対策を講じること。
    - **解説**: 固有安全、機能安全、フォールトトレランス、フェイルセーフ、フェイルソフトなどが含まれる。
22. **安全機能に対するテスト**:
    - **定義**: システムの安全機能（例: 緊急停止機能、安全インターロック）が、設計通りに動作し、危害を防止できるかを確認するテスト。
    - **解説**: 特にセーフティ・クリティカルシステムにおいて重要となる。
23. **安全性解析**:
    - **定義**: システムの設計段階で、潜在的なハザードを特定し、そのリスクを評価し、安全対策の有効性を検証する活動。
    - **解説**: FMEA、FTA、HAZOP、STAMP/STPAなどの手法が用いられる。
24. **安全度水準**:
    - **定義**: 既出。SIL（Safety Integrity Level）と同義。
    - **解説**: 機能安全規格（IEC 61508など）において、安全機能が要求される安全性を達成する度合いを示す指標。
25. **機能不動作**:
    - **定義**: システムが、本来果たすべき機能を果たさない状態。故障の一種。
    - **解説**: セーフティ・クリティカルシステムにおいては、機能不動作が重大な危害に繋がる可能性がある。
26. **故障モード**:
    - **定義**: 既出。システムやコンポーネントが故障した際に、外部から観測される故障の現れ方、分類。
    - **解説**: FMEAなどで分析される。
27. **仕様の穴**:
    - **定義**: 仕様書に記載されていない、または曖昧な部分。これが原因で、設計や実装に誤りが生じたり、予期せぬ振る舞いを引き起こしたりする可能性がある。
    - **解説**: レビューや形式手法によって早期に発見し、解消することが重要。
28. **設計および実装障害**:
    - **定義**: 設計段階や実装段階で作り込まれた欠陥（フォールト）。
    - **解説**: これらが原因で、システムが誤動作したり、危害を引き起こしたりする可能性がある。
29. **非定常入力**:
    - **定義**: システムが通常想定しない、または予期しない入力。例えば、異常なデータ、不正な操作、同時多発的なイベントなど。
    - **解説**: 非定常入力に対するシステムの振る舞いをテストすることで、システムの堅牢性や安全性を評価できる。

---

## 📌 頻出論点／出題パターン
- **フォールト・アボイダンスとフォールト・トレランスの違い**: フォールト・アボイダンスが「欠陥の混入を未然に防ぐ」のに対し、フォールト・トレランスが「欠陥が発生してもサービスを継続する」という違いは頻出。前者が予防、後者が回復の考え方。
- **フェイルセーフとフェイルソフトの違い**: フェイルセーフが「安全な状態に移行する」のに対し、フェイルソフトが「最低限のサービスを継続する」という違いを理解する。
- **アクティブセーフティとパッシブセーフティの違い**: アクティブセーフティが「事故を未然に防ぐ」のに対し、パッシブセーフティが「事故発生時の被害を軽減する」という違いを理解する。
- **STAMP/STPAの目的**: 従来の故障連鎖モデルでは捉えきれない、システム全体の制御構造や相互作用に起因する事故を分析するという目的を理解する。
- **MC/DCの目的**: 極めて高い安全性が求められるシステムで用いられる網羅基準であり、各条件が決定の真偽に独立して影響を与えることを確認するという目的を理解する。
